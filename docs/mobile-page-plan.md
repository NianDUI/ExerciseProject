# 手机页面方案

## 1. 目标

面向当前 `fictionweb` 项目，手机页面建议聚焦两个核心场景：

1. 阅读场景：用户在手机上快速找书、看章节、连续阅读。
2. 轻管理场景：用户在手机上做少量高频操作，例如搜索书籍、查看采集状态、触发“获取后续”。

不建议第一期在手机端完整照搬后台管理能力。原因是现有后台包含大量表格、批量操作、复杂表单，直接移动化会导致交互成本很高。

## 2. 现状判断

仓库里已经有一版旧移动页：

- 入口：`/m/list.html`
- 技术：`Vue2 + Vue Router 2 + Vonic + axios`
- 已有能力：
  - 书籍列表
  - 章节列表
  - 正文阅读
- 已接接口：
  - `POST /api/queryBookList`
  - `POST /api/queryChapterList`
  - `GET /api/queryChapterInfo/{id}`

这版可以用，但有几个明显问题：

1. 依赖老旧，维护成本高。
2. 页面是单文件静态实现，后续扩展管理能力会越来越重。
3. UI 偏早期 H5 风格，阅读体验和信息层级都比较弱。

## 3. 方案定位

建议新做一版“移动阅读优先”的手机端，路线如下：

- 技术上沿用现有 `modern` 体系，统一到 `Vue3 + Element Plus + axios`
- 入口单独提供，例如：`/modern/mobile`
- 视觉上做成“阅读 App 风格”，不是后台表格缩小版
- 功能上分两期：
  - 一期：阅读闭环
  - 二期：轻量管理

这样可以最大化复用现有 `modern/js/common/http.js`、`auth.js` 和已有接口，同时避免维护两套完全不同的前端技术栈。

## 4. 信息架构

建议底部 4 个一级导航：

1. 书城
2. 书架
3. 文件
4. 我的

如果第一期时间有限，可以先做 2 个一级导航：

1. 书城
2. 文件

### 4.1 书城

用于找书和进入章节列表。

页面内容建议：

- 顶部搜索框
- 最近阅读/继续阅读卡片
- 书籍列表卡片
- 分页改为“加载更多”，不要保留 PC 式上一页/下一页

每个书籍卡片展示：

- 书名
- 站点名
- 配置名
- 任务状态
- 最近更新时间
- 主操作按钮：`继续阅读` / `查看目录`

### 4.2 目录页

对应某本书的章节列表。

页面内容建议：

- 吸顶书籍信息头部
- 章节搜索
- 排序切换：正序 / 倒序
- 章节列表
- 快速定位到最近阅读章节

章节项展示：

- 章节名
- 原名称（弱化展示）
- 创建时间
- 阅读状态标记

### 4.3 阅读页

这是手机端的核心页面，建议重点打磨。

页面结构建议：

- 顶部极简标题栏
- 正文内容区
- 底部悬浮操作条

底部操作条包含：

- 上一章
- 目录
- 下一章
- 设置

阅读设置建议支持：

- 字号
- 行高
- 页面宽度
- 主题色
  - 米白
  - 浅绿
  - 深色

阅读页还应增加：

- 自动记录阅读进度
- 进入页面自动滚动到上次阅读位置
- 点击段落区域呼出/隐藏工具栏

### 4.4 书架

如果要做一期增强，可以加一个轻量书架页。

数据来源第一期可以先走本地存储，不必等后端新接口：

- 最近阅读书籍
- 最近阅读章节
- 阅读时间

这样即使后端不改接口，也能先形成“继续阅读”体验。

### 4.5 文件管理

手机端文件管理建议做成“轻浏览 + 轻预览 + 下载”的模式，不建议做复杂的上传、重命名、删除。

原因：

1. 当前后端已经具备文件浏览和下载能力，适合先快速落地。
2. 手机端更适合消费型操作，不适合复杂文件运维。
3. 现有项目里已经有视频文件访问场景，手机端补齐后实用性会比较高。

页面内容建议：

- 当前路径面包屑
- 返回上级目录按钮
- 文件/目录列表
- 文件类型图标
- 视频文件直接预览
- 其他文件走下载或打开

列表项展示：

- 文件名
- 是否目录
- 文件大小
- 修改时间

每个文件项可支持的动作：

- 目录：进入目录
- 视频：在线播放
- 文本：在线查看前几屏或跳转读取页
- 其他：直接下载

建议把“文件管理”放到一级导航里，而不是隐藏到“我的”下面。因为它属于高频功能，且和阅读内容、下载资源关系紧密。

### 4.6 我的

第一期只放轻功能：

- Token 设置
- 清除缓存
- 阅读偏好设置
- 关于项目

## 6. 接口复用方案

基于当前后端，第一期不需要新增接口也能落地：

### 6.1 书籍列表

- 接口：`POST /api/queryBookList`
- 用途：首页书籍列表、搜索

建议入参：

```json
{
  "name": "",
  "pageNum": 1,
  "pageSize": 10
}
```

### 6.2 章节列表

- 接口：`POST /api/queryChapterList`
- 用途：目录页、章节搜索

建议入参：

```json
{
  "name": "",
  "bookid": 1,
  "pageNum": 1,
  "pageSize": 20
}
```

### 6.3 章节正文

- 接口：`GET /api/queryChapterInfo/{id}`
- 用途：阅读页正文、上一章/下一章切换

从旧移动页实现来看，返回值里已经包含：

- `book`
- `chapter`
- `paragraphList`
- `previd`
- `nextid`

这非常适合直接支撑阅读页。

### 6.4 文件列表

- 接口：`GET /api/file/list/**`
- 用途：文件管理页目录浏览

说明：

- 根目录可请求：`/api/file/list/`
- 子目录可请求：`/api/file/list/{path}`

返回数据从现有 `modern` 文件页逻辑看，已经足够支持手机端展示：

- `name`
- `path`
- `isDir`
- `size`
- `unit`
- `lastModified`

### 6.5 当前路径

- 接口：`GET /api/file/path` 或 `GET /api/file/path/**`
- 用途：展示当前路径名、面包屑

### 6.6 文件下载

- 接口：`GET /api/file/download/**`
- 用途：下载文件、视频预览

### 6.7 文件读取

- 接口：`GET /api/file/read?path=xxx`
- 用途：文本文件在线查看

建议第一期只对以下类型开放在线预览：

- `mp4`
- `mkv`
- `webm`
- `txt`
- `log`

其他类型统一下载，避免手机端预览体验过重。

## 7. 交互策略

## 7.1 搜索

- 首页搜索书籍
- 目录页搜索章节
- 输入后 300ms 防抖
- 保留最近搜索关键词

## 7.2 翻页

- 目录页使用“加载更多”
- 阅读页使用按钮切章
- 后续可补充左右滑动切章，但不建议第一期做，容易和浏览器返回手势冲突

## 7.3 续读

建议把以下信息存本地缓存：

- `bookId`
- `bookName`
- `chapterId`
- `chapterName`
- `scrollTop`
- `updatedAt`

进入首页时优先展示“继续阅读”卡片。

## 7.4 Token

当前项目接口统一依赖 token，且 `modern/js/common/auth.js` 已支持：

- prompt 输入
- sessionStorage
- Cookie 持久化

手机端建议改成页面内设置，而不是 `prompt` 弹窗，交互会更自然。

## 7.5 文件管理交互

- 默认进入根目录
- 点击目录进入子目录
- 顶部固定显示当前路径
- 提供“上级目录”快速返回
- 视频文件在弹层或新页面内播放
- 文本文件使用轻量阅读页展示
- 非预览类型直接触发下载

如果目录层级较深，建议把路径做成横向可滚动面包屑，避免手机端一行放不下。

## 8. 视觉方向

建议不要做成传统后台蓝白风，而是更偏阅读产品：

- 主色：深墨绿或暖棕
- 背景：米白、浅卡其、浅绿三套阅读主题
- 字体：正文优先用衬线或更有阅读感的中文字体回退栈
- 卡片：圆角 16px 左右，弱阴影
- 间距：大留白，保证正文呼吸感

推荐视觉关键词：

- 安静
- 沉浸
- 轻操作
- 长时间阅读不累

## 9. 技术落地建议

建议目录：

```text
src/main/resources/templates/modern/mobile.html
src/main/resources/static/modern-mobile/css/app.css
src/main/resources/static/modern-mobile/js/app.js
src/main/resources/static/modern-mobile/js/router/index.js
src/main/resources/static/modern-mobile/js/pages/home.js
src/main/resources/static/modern-mobile/js/pages/catalog.js
src/main/resources/static/modern-mobile/js/pages/reader.js
src/main/resources/static/modern-mobile/js/pages/file-list.js
src/main/resources/static/modern-mobile/js/pages/file-viewer.js
src/main/resources/static/modern-mobile/js/common/storage.js
```

原因：

1. 与旧 `/m/list.html` 隔离，风险低。
2. 与现有 `modern` 后台并行，职责清晰。
3. 后续如果想把移动端独立部署，也方便迁移。

## 10. 分期建议

### 第一阶段：可上线最小版

目标：先形成完整阅读闭环。

包含：

- 手机首页
- 书籍搜索
- 目录页
- 阅读页
- 文件管理页
- 视频预览
- 本地续读
- Token 设置页

### 第二阶段：增强版

包含：

- 书架
- 阅读主题设置
- 最近阅读历史
- 章节排序/快速定位
- 文本文件在线查看
- 更好的加载骨架屏和空状态

### 第三阶段：轻管理

如果确实有手机管理需求，再补：

- 查看任务状态
- 手动触发“获取后续”
- 查看最新章节数量
- 文件删除、上传、重命名（如果后端后续补接口）

不建议在手机端做：

- 大批量删除
- 复杂配置编辑
- 长表单新增书籍/配置

## 11. 我对这次方案的推荐结论

如果要我给一个最适合当前项目的方案，我会推荐：

1. 保留旧 `/m/list.html` 作为临时入口，不继续扩展。
2. 新做 `modern mobile` 版本，统一到 `Vue3` 体系。
3. 第一版只做“书籍列表 + 目录 + 阅读 + 续读 + token 设置”。
4. 把“文件管理”纳入第一版，但只做浏览、预览、下载。
5. 不急着把后台管理完整搬到手机端。

这样投入最小，体验提升最大，也最符合这个项目现在已经具备的接口能力。
